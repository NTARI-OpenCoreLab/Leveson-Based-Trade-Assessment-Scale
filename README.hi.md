# Leveson-आधारित व्यापार मूल्यांकन पैमाना (LBTAS)

Nancy Leveson की विमान सॉफ़्टवेयर मूल्यांकन पद्धति पर आधारित, द्विदिशात्मक मूल्यांकन मानदंडों के साथ, डिजिटल वाणिज्य के लिए एक रेटिंग प्रणाली।

## अवलोकन

Leveson-आधारित व्यापार मूल्यांकन पैमाना (LBTAS), Nancy Leveson की विमान सॉफ़्टवेयर मूल्यांकन पद्धति को लागू करता है, जो एयरोस्पेस अनुप्रयोगों के लिए विकसित की गई थी और जिसे डिजिटल वाणिज्य तथा आर्थिक मूल्यांकन के संदर्भों के लिए अनुकूलित किया गया है। LBTAS 6-बिंदु पैमाने का उपयोग करके लेन-देन की गुणवत्ता का डेटा एकत्र करने के लिए एक फ़्रेमवर्क प्रदान करता है।

## पारंपरिक रेटिंग प्रणालियों की समस्या

5-स्टार प्रणालियाँ ऐसा डेटा प्रदान नहीं करतीं जो उत्पादकों को सुधार के लिए प्रेरित करे। 5-स्टार प्रणाली 1958 में Forbes Travel Guide (पूर्व में Mobil Travel Guide) द्वारा अमेरिकी अंतरराज्यीय राजमार्गों पर होटलों की गुणवत्ता का विज्ञापन करने के लिए विकसित की गई थी। इसे राजमार्ग यात्रा के लिए एकतरफ़ा संचार प्रणाली के रूप में डिज़ाइन किया गया था, डिजिटल वाणिज्य के लिए नहीं।

**सीमाएँ:**
- ई-कॉमर्स संदर्भों में रेटिंग सीमित मूल्य ही प्रदान करती हैं
- PR मैनेजर नीति परिवर्तन में बाधाएँ खड़ी करते हैं
- ग्रैन्युलैरिटी लेन-देन की जटिलता को पकड़ने में विफल रहती है
- एकदिशात्मक मूल्यांकन उपभोक्ता की जवाबदेही की अनदेखी करता है
- डेटा की अपर्याप्तता के कारण कमेंट सेक्शन पर निर्भरता बढ़ जाती है

## Leveson दृष्टिकोण ही क्यों?

Leveson प्रणाली की उत्पत्ति विमान सॉफ़्टवेयर विकास से हुई है, जहाँ सिस्टम की विफलता का परिणाम जीवन की हानि या R&D निवेश की बर्बादी होता है। यह पद्धति:

- श्रेणी परिभाषाओं के साथ 6-बिंदु पैमाने (+4 से -1 तक) का उपयोग करती है
- प्रत्येक रेटिंग स्तर में अर्थ को संक्षिप्त रूप से समाहित करती है
- डेटा के लिए कमेंट सेक्शन पर निर्भरता कम करती है
- द्विदिशात्मक मूल्यांकन (उत्पादक और उपभोक्ता दोनों का) सक्षम बनाती है
- डेटा-आधारित सुधार चक्रों का समर्थन करती है

## पैमाने की परिभाषाएँ

### +4 **प्रसन्नता (Delight)**
इंटरैक्शन लेन-देन के बाद उपयोगकर्ता की प्रथाओं और चिंताओं के विकास का पूर्वानुमान करता है

### +3 **कोई नकारात्मक परिणाम नहीं (No Negative Consequences)**
इंटरैक्शन हानि रोकने के लिए डिज़ाइन किया गया है, बुनियादी गुणवत्ता मानकों से आगे जाता है

### +2 **बुनियादी संतुष्टि (Basic Satisfaction)**
इंटरैक्शन सामाजिक रूप से स्वीकार्य मानकों को पूरा करता है, उपयोगकर्ता की व्यक्त की गई माँगों से आगे जाता है

### +1 **बुनियादी वादा (Basic Promise)**
इंटरैक्शन उपयोगकर्ता की सभी व्यक्त की गई माँगों को पूरा करता है, उससे अधिक कुछ नहीं

### 0 **निंदक संतुष्टि (Cynical Satisfaction)**
इंटरैक्शन एक ऐसा बुनियादी वादा पूरा करता है जिसमें उपयोगकर्ता की संतुष्टि के प्रति बहुत कम या कोई अनुशासन नहीं दिखता

### -1 **कोई भरोसा नहीं (No Trust)**
उपयोगकर्ता को नुकसान पहुँचाया गया, उसका शोषण किया गया, या उसे ऐसा उत्पाद/सेवा मिली जिसमें अनुशासन के अभाव या दुर्भावनापूर्ण इरादे के प्रमाण हों

## द्विदिशात्मक मूल्यांकन

LBTAS दोनों पक्षों की रेटिंग बनाए रखकर डिजिटल नेटवर्कों में दोतरफ़ा जवाबदेही सक्षम बनाता है:

- **उत्पादक (Producers)**: प्रदाताओं की पहचान करता है
- **उपभोक्ता (Consumers)**: ग्राहकों की पहचान करता है

यह दृष्टिकोण सामुदायिक स्व-नियमन को सुगम बनाता है और केंद्रीकृत मॉडरेशन की आवश्यकता को कम करता है।

## प्रतिष्ठा (रेप्युटेशन) को पढ़ना

रेटिंग का कभी औसत नहीं निकाला जाता। प्रतिष्ठा प्रत्येक स्तर (`-1` से `+4` तक) पर प्राप्त रेटिंग की गिनती तथा कुल योग होती है। कुल योग का अपने आप में महत्व है: यह लेन-देन की मात्रा को और परोक्ष रूप से सेवा में बिताए समय को दर्शाता है। 5,000 रेटिंग पर एक साफ़-सुथरा वितरण, केवल 5 रेटिंग पर उसी आकार के वितरण की तुलना में कहीं अधिक मज़बूत संकेत है — और औसत निकालने से यह अंतर मिट जाता, क्योंकि दोनों एक ही संख्या में सिमट जाते। (यह गिनती रेटिंग की गिनती है; लेन-देन और कार्यकाल के सटीक आँकड़े API से मिलते हैं, जो प्रत्येक रेटिंग घटना पर टाइमस्टैम्प लगाता है।)

`-1` ("कोई भरोसा नहीं") को कभी हल्का नहीं पड़ने दिया जाता: `report` कमांड हर उस एक्सचेंज को, जिसे एक या अधिक `-1` रेटिंग मिली हैं, `harm_flagged` सूची में सामने लाता है, और `list` किसी भी `-1` वाले एक्सचेंज के साथ हानि-चिह्न (हार्म फ़्लैग) जोड़ देता है।

## विशेषताएँ

- **पद्धति**: एयरोस्पेस मूल्यांकन फ़्रेमवर्कों पर आधारित
- **द्विदिशात्मक मूल्यांकन**: लेन-देन में दोनों पक्षों को रेट करें
- **ग्रैन्युलैरिटी**: परिभाषाओं के साथ 6-बिंदु पैमाना
- **डिपेंडेंसी**: सिस्टम में इंटीग्रेशन
- **डेटाबेस सपोर्ट**: पर्सिस्टेंस लेयर का समर्थन
- **ओपन सोर्स**: समुदाय-संचालित विकास और अनुकूलन

## इंस्टॉलेशन

```bash
# Clone the repository
git clone https://github.com/NTARI-OpenCoreLab/Leveson-Based-Trade-Assessment-Scale.git
cd Leveson-Based-Trade-Assessment-Scale

# Make executable (optional)
chmod +x lbtas.py

# Run directly
python3 lbtas.py --help
```

किसी बाहरी डिपेंडेंसी की आवश्यकता नहीं। केवल Python 3 की स्टैंडर्ड लाइब्रेरी का उपयोग करता है।

## त्वरित शुरुआत

```python
from lbtas import LevesonRatingSystem

# Initialize the rating system
rating_system = LevesonRatingSystem()

# Add an exchange (transaction)
rating_system.add_exchange("transaction_001")

# Add ratings (categories: reliability, usability, performance, support)
rating_system.add_rating(
    exchange_name="transaction_001",
    criterion="reliability",
    rating=3  # No Negative Consequences
)

# Read the distribution (ratings are never averaged)
ratings = rating_system.view_ratings("transaction_001")
print(ratings["reliability"])
# {'distribution': {'-1': 0, '0': 0, '1': 0, '2': 0, '3': 1, '4': 0}, 'total': 1}
```

### कमांड लाइन इंटरफ़ेस

```bash
# Interactive rating
python3 lbtas.py rate --exchange "MyService"

# Programmatic rating
python3 lbtas.py add --exchange "MyService" --criterion reliability --rating 3

# View ratings
python3 lbtas.py view --exchange "MyService"

# Generate report
python3 lbtas.py report

# Export data
python3 lbtas.py export --format json --output ratings.json
```

## स्टोरेज

LBTAS पर्सिस्टेंस के लिए JSON फ़ाइल स्टोरेज का उपयोग करता है:

```python
# Initialize with storage file
rating_system = LevesonRatingSystem(storage_file='ratings.json')

# Ratings are saved automatically to the file
rating_system.add_exchange("service_001")
rating_system.add_rating("service_001", "reliability", 3)
```

स्टोरेज फ़ाइल का फ़ॉर्मैट:
```json
{
  "service_001": {
    "reliability": [3, 4, 3],
    "usability": [2, 3],
    "performance": [4],
    "support": [3, 3, 2],
    "_metadata": {
      "created": "2024-09-04T10:30:00",
      "total_ratings": 10
    }
  }
}
```

### रेटिंग श्रेणियाँ

डिफ़ॉल्ट श्रेणियाँ:
- **विश्वसनीयता (Reliability)**: भरोसेमंदी और निरंतरता
- **उपयोगिता (Usability)**: उपयोग में आसानी और उपयोगकर्ता अनुभव
- **परफ़ॉर्मेंस (Performance)**: गति और दक्षता
- **सपोर्ट (Support)**: ग्राहक सेवा की गुणवत्ता

इनिशियलाइज़ेशन के दौरान कस्टम श्रेणियाँ परिभाषित की जा सकती हैं।

## उपयोग के मामले

### अकादमिक अनुसंधान
- अध्ययन करें कि रेटिंग पैमाने का डिज़ाइन उपयोगकर्ता व्यवहार और बाज़ार परिणामों को कैसे प्रभावित करता है
- भरोसे और सहयोग पर द्विदिशात्मक मूल्यांकन के प्रभावों को मापें
- मौजूदा फ़्रेमवर्कों के विकल्प के रूप में गुणवत्ता-आधारित मूल्यांकन का विश्लेषण करें

### ई-कॉमर्स प्लेटफ़ॉर्म
- मार्केटप्लेस लेन-देन के लिए गुणवत्ता मेट्रिक्स लागू करें
- समुदाय-संचालित प्रतिष्ठा प्रणालियाँ सक्षम बनाएँ
- स्व-नियमन के माध्यम से मॉडरेशन का बोझ कम करें

### डिजिटल सहकारी संस्थाएँ
- पीयर-टू-पीयर जवाबदेही को सुगम बनाएँ
- गवर्नेंस संरचनाओं का समर्थन करें
- डेटा-आधारित नीति सुधार सक्षम बनाएँ

## आर्किटेक्चर

LBTAS एक एकल Python मॉड्यूल के रूप में लागू किया गया है, जिसमें शामिल हैं:

1. **कोर क्लास**: `LevesonRatingSystem` रेटिंग और स्टोरेज का प्रबंधन करती है
2. **JSON पर्सिस्टेंस**: स्वचालित सेव के साथ फ़ाइल-आधारित स्टोरेज
3. **CLI इंटरफ़ेस**: इंटरैक्टिव और प्रोग्रामेटिक उपयोग के लिए कमांड-लाइन टूल
4. **कोई बाहरी डिपेंडेंसी नहीं**: केवल Python स्टैंडर्ड लाइब्रेरी का उपयोग करता है

प्रणाली निम्नलिखित का समर्थन करती है:
- इंटरैक्टिव रेटिंग संग्रह
- प्रोग्रामेटिक रेटिंग सबमिशन
- कस्टम रेटिंग श्रेणियाँ
- रिपोर्ट जनरेशन और डेटा एक्सपोर्ट
